# 层级规范与变更记录（选举业务页统一两级结构）

## 一、统一层级铁律（所有选举业务页必须一致）

选举类内部页面一律两级，**禁止跨届扁平大表、禁止用右上角下拉切换届**：

1. **第一级 = 历届活动列表**：侧边栏点进来先看到历届选举活动，每行一届
   （届次 / 活动名称(提案名) / 选举方式 / 正式选举日D / 该届统计 / 状态 / 操作）。
2. **第二级 = 该届明细**：点「查看本届/材料/候选人/公告」进入，顶部有 `SessionDetailBar`
   （← 返回历届列表 + 届次 + 活动名 + 方式 + Dday），下面才是这一届的业务表。

数据源头：每届活动来自提案审批通过状态机（`useActivities()` / 后端 elections）。
任何业务明细（材料、候选人、公告、岗位）都必须带 `activityId/election_id` 归属到某一届，绝不跨届混表。

## 六、活动详情页 = 左流程 + 右「小编工作台」（2026-09-01 定，编辑唯一入口）

### 6.1 设计决策（用户拍板，不可回退）
- 小编/管理员**只在「选举活动 → 某届详情」这一个页面做完一个阶段的全部事**，不跳其他页面：
  编辑公告正文、预览公文、立即/定时发布、日程提醒（提早 N 小时 + 提醒发给谁）、
  上传/外链下载资料、开放材料提交、查看已上传材料、更新候选人展示。
- 独立的「公告通知」菜单页**降级为公告模板库（只读查阅）**，不再是编辑入口；
  待办：把 `pages/Election/Announcements` 第二级改为只读模板浏览（去掉编辑/发布按钮，加"请到活动详情编辑"提示）。
- 布局：`mainGrid` 左右两栏（断点 ≤920px 退化为单栏，右栏取消 sticky）。
  - 左栏 `leftCol`：只读时间轴（Timeline mode='same'），阶段卡片可点选，选中蓝框 +「编辑中」Tag；保留三色（当前红/已过绿/未到灰）。
  - 右栏 `workCol`：position:sticky 置顶、自身滚动，随左栏选中阶段切换内容。

### 6.2 右栏工作台内容（pages/Election/ActivityDetail/index.tsx）
- 阶段头：阶段名 + 日期区间 + D 偏移 + 轮次 Tag；该阶段无公告时提示"线下推进即可"。
- 多份公告：`Radio.Group` 切换（如 D-34 的 1/2/3 号），左栏公告号小 Tag 可点 = 选阶段并定位该公告。
- 公告标题 Input + 正文 Textarea（模板预填，【】占位、日期/届次预览时代入）；预览公文 Dialog、重置为模板。
- 资料：上传按钮（接 POST /api/files/upload，bucket=public-download）+ 外链 Input 双保险；
  有材料类型时显示「开放材料提交」Switch（开启后小程序公告下出现提交材料按钮）。
- 发布：Radio 立即/定时，定时显示 datetime-local；
  日程提醒 = InputNumber 提早小时 + Checkbox.Group（编辑经办 editor / 管理员 admin）；
  底部「保存草稿 / 确认发布（定时时文案=设定定时发布）」。定时未选时间点发布给 warning。
- 阶段其他事项按类型出现：查看已上传材料（GET /api/materials?electionId&stageKey）、更新候选人展示（PUT /api/candidates/result）。
