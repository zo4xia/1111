# 封地契约 — 城厢区村居换届选举系统

> 治理框架：项目=国家，功能模块=封地。每个封地有独一无二的作用（唯一性），
> 封地之间通过清晰的商贸线（业务流/入参/出参）往来。
> 不是唯一就会挤兑乱价（两个真相）。
> 每个封地的领主（维护者/agent）必须落笔写下：我是谁、我供应什么、我缺什么。

---

## 封地总览

| 封地 | 唯一性定位 | 领主（维护方） | 写/读 |
|---|---|---|---|
| 提案审批 | 选举创建唯一入口 | 后台·审核员 | 写 |
| 小编工作台 | 公告内容编辑唯一入口 | 后台·编辑经办 | 写 |
| 公告记录 | 公告发布状态台账 | 后台·只读 | 只读 |
| 材料提交（选民端） | 选民材料上传唯一入口 | 小程序 | 写 |
| 材料审核 | 材料审核结果回填唯一入口 | 后台·甲方线下 | 写（回填） |
| 候选人管理 | 四轮审核结果回填唯一入口 | 后台·甲方线下 | 写（回填） |
| 小程序公告 | 公告只读展示+附件下载 | 小程序 | 只读 |
| 小程序岗位 | 岗位信息只读展示 | 小程序 | 只读 |
| 文件服务 | 所有附件唯一存储/下载 | 后端·静态 | 读写 |

## 1. 封地：提案审批

**我是谁**：选举创建的唯一入口。一届选举从这里诞生，没有第二条路。

**我供应什么（出参）**：
- 提案记录（proposal_id、D日、岗位清单、说明）
- 审核通过后触发事务：自动生成该届日程表（18阶段）、公告模板（18条草稿）、岗位需求记录

**我缺什么（入参）**：
- D日（选举正式日期）
- 换届选举岗位信息（岗位类型/名额/说明）
- 详细说明
- （不传公告文档——公告由模板库生成，小编工作台改）

**商贸线**：
- 提案 → 审核员审核通过 → 事务生成器 → 活动列表（日程）、小编工作台（公告草稿）、岗位管理（岗位记录）
- 审核不通过 → 退回编辑

**唯一性红线**：不在其他地方创建选举、不在这里编辑公告内容。

---

## 2. 封地：小编工作台（活动列表·当届时间轴）

**我是谁**：公告内容编辑的唯一写入口。标题、正文、落款、成文日期、发布方式、定时、提醒、材料开关，全在这里改。

**我供应什么（出参）**：
- 更新后的公告记录（PUT /api/announcements/:id）
- 公告附件上传（POST /api/announcements/:id/file → /api/files/announcements/<id>/）
- 发布操作（PUT /api/announcements/:id/publish → 状态变 published）

**我缺什么（入参）**：
- 公告ID
- 编辑字段：annTitle / annContent / annCode / annSign / annSignDate / annOpenMaterialSubmit / annPublishMode / annPublishAt / annRemindHours / annRemindTo

**商贸线**：
- 从事务生成器接收公告草稿（18条）
- 编辑后 → 公告记录（状态同步）、小程序公告（拉取展示）、文件服务（附件存储）

**唯一性红线**：公告记录页不编辑内容，只看状态。不在小程序端编辑公告。

---

## 3. 封地：公告记录（公告管理）

**我是谁**：公告发布状态的只读台账。只记录"发没发、什么时候发的"，不碰内容。

**我供应什么（出参）**：
- 公告列表（含 annStatus / annPublishTime / annEditor）
- 公文预览（NoticeDoc 组件，只读渲染）

**我缺什么（入参）**：无（只读，从 /api/announcements 拉取）

**商贸线**：
- 从小编工作台接收状态变更（published/draft）
- 向用户展示台账 + 公文预览

**唯一性红线**：这里没有编辑按钮。编辑一律跳小编工作台。

---

## 4. 封地：材料提交（选民端·小程序）

**我是谁**：选民/参选人上传材料的唯一入口。下载模板→填写→上传，全流程在这里。

**我供应什么（出参）**：
- 材料记录（POST /api/mp/materials → mat_status='pending'）
- 材料附件（POST /api/materials/:id/upload → /api/files/materials/<id>/）
- 我的提交记录（GET /api/mp/materials/mine）

**我缺什么（入参）**：
- positionId（竞选岗位，默认'委员'）
- note（备注）
- 附件文件（自荐表/身份证/无犯罪证明等，按材料类型分）
- JWT 用户身份（orgId/phone/name 从 token 取，不手填）

**商贸线**：
- 从文件服务下载模板（/api/files/material_templates/）
- 提交后 → 材料审核封地（待审）、文件服务（附件归档）

**唯一性红线**：选民只能从这里提交，后台不代交选民材料（后台 /api/materials 是组织推荐内推，mat_type='组织推荐'，跟选民的'个人自荐'是两条线）。

---

## 5. 封地：材料审核

**我是谁**：材料审核结果的唯一回填入口。甲方线下审核后，把结果录进系统。

**我供应什么（出参）**：
- 审核结果（PUT /api/materials/:id/review → mat_status / matReviewTime / matReviewComment）
- 审核通过 → 自动入候选人池（candidates）

**我缺什么（入参）**：
- 材料ID
- 审核结果（通过/不通过）
- 审核备注（可选）

**商贸线**：
- 从材料提交封地接收待审材料
- 审核通过 → 候选人管理封地（生成候选人记录）
- 审核不通过 → 通知选民（小程序消息）

**唯一性红线**：审核结果只从这里录，不在候选人管理里改材料状态。

---

## 6. 封地：候选人管理

**我是谁**：四轮审核（初审/预选/联审/考察）结果的唯一回填入口。甲方线下走完一轮，录一轮结果。

**我供应什么（出参）**：
- 轮次结果（PUT /api/candidates/:id/round → cand_r1~r4 / reviewer / time / comment）
- 状态自动派生（deriveStatus：通过→下一轮，不通过→退出）
- 最终当选/落选（cand_votes 录入后）

**我缺什么（入参）**：
- 候选人ID
- 轮次（1-4）
- 结果（通过/不通过）
- 理由（可选）

**商贸线**：
- 从材料审核封地接收入池候选人
- 每轮结果 → 小程序公告（公示）、选举结果封地

**唯一性红线**：候选人状态由轮次结果自动派生，不手改 cand_status。

---

## 7. 封地：小程序公告

**我是谁**：公告的只读展示窗口。选民看公告、下载附件，全在这里。

**我供应什么（出参）**：
- 公告列表（按发布时间排序，未到日期的灰度未解锁）
- 公告详情（正文 + 附件下载列表）
- 附件下载（wx.downloadFile + wx.openDocument）

**我缺什么（入参）**：无（只读，从 /api/announcements 拉取，annFiles 随每条公告返回）

**商贸线**：
- 从小编工作台接收公告内容和状态
- 从文件服务下载附件

**唯一性红线**：这里不编辑、不发布。切换公告时附件列表随当前公告变化（不是死链接）。

---

## 8. 封地：小程序岗位

**我是谁**：岗位信息的只读展示窗口。参选人看有哪些岗位、名额多少、要求是什么。

**我供应什么（出参）**：
- 岗位列表（posType / posQuota / posDesc / posStatus）
- 每个岗位的"提交材料"入口 → 跳材料提交封地

**我缺什么（入参）**：无（只读，从 /api/positions 拉取）

**商贸线**：
- 从事务生成器接收岗位记录
- 向材料提交封地传递 positionId

**唯一性红线**：岗位信息不在小程序编辑，名额/状态由后台管理。

---

## 9. 封地：文件服务

**我是谁**：所有附件的唯一存储和下载入口。公告附件、材料附件、模板文件，全在这里。

**我供应什么（出参）**：
- 文件下载 URL（/api/files/<分类>/<id>/<文件名>）
- 目录结构：
  - 公告附件：uploads/announcements/<公告ID>/
  - 材料附件：uploads/materials/<材料ID>/
  - 材料模板：uploads/material_templates/
  - 归档目录（D-012）：uploads/materials/<归属地>/<届>/<分类>/<归属地>-<届>-<时间>-<岗位>-<提交人>/

**我缺什么（入参）**：
- 文件上传（multer，单文件 ≤20MB）
- 分类目录和ID（由调用封地指定）

**商贸线**：
- 小编工作台 → 公告附件
- 材料提交 → 材料附件
- 所有封地 → 下载（express.static 公开服务）

**唯一性红线**：文件只存一份，URL 全局唯一。不在数据库里存文件内容，只存 URL 引用。

## 商贸线总图

```
提案审批 ──审核通过──→ 事务生成器
                          ├──→ 活动列表（日程）
                          ├──→ 小编工作台（公告草稿18条）
                          └──→ 岗位管理（岗位记录）

小编工作台 ──编辑/发布──→ 公告记录（状态台账）
     │                        │
     └──附件──→ 文件服务 ←──附件── 材料提交（选民端）
                    │              │
                    │         审核通过
                    │              ↓
小程序公告 ←──拉取──┘         材料审核 ──→ 候选人管理 ──→ 选举结果
小程序岗位 ←──拉取──────────────────────────┘
```

## 唯一性检查清单（每次改代码前过一遍）

- [ ] 这个功能有没有其他封地也在做？（有→合并，留唯一入口）
- [ ] 入参是不是只从一个口子进？（不是→收口）
- [ ] 出参是不是只供应给明确的下游？（不是→划清边界）
- [ ] 有没有两个地方都能改同一份数据？（有→只留一个写入口，另一个改只读）
- [ ] 文件是不是只存一份、URL 唯一？（不是→去文件服务统一管）

## 领主制（Agent 封地自治）

> 每个封地有一个小领主（agent）负责打理。领主必须喊清三句话：
> **我是干嘛的（唯一性定位）、我供应啥（出参）、我缺啥（入参）。**
> 三句话喊清楚，上下游自动匹配，不用中央调度。

| 封地 | 领主（agent） | 三句话 |
|---|---|---|
| 提案审批 | 提案官 | 我管选举创建唯一入口；供应提案+事务生成触发；缺D日+岗位信息+说明 |
| 小编工作台 | 编辑官 | 我管公告内容唯一写入口；供应更新后公告+附件+发布；缺公告ID+编辑字段 |
| 公告记录 | 台账官 | 我管公告状态只读台账；供应发布状态+公文预览；缺无（只读） |
| 材料提交（选民） | 材料官 | 我管选民材料上传唯一入口；供应pending材料+附件；缺positionId+note+文件 |
| 材料审核 | 审核官 | 我管材料结果回填唯一入口；供应审核结果+入池触发；缺材料ID+结果+备注 |
| 候选人管理 | 选务官 | 我管四轮审核回填唯一入口；供应轮次结果+状态派生；缺候选人ID+轮次+结果 |
| 小程序公告 | 传声官 | 我管公告只读展示；供应公告列表+详情+附件下载；缺无（只读拉取） |
| 小程序岗位 | 展示官 | 我管岗位只读展示；供应岗位列表+提交入口；缺无（只读拉取） |
| 文件服务 | 库吏 | 我管所有附件唯一存储；供应文件URL；缺文件上传+分类目录 |

**领主协作规则**：
1. 领主只在自己封地里改代码，不越界
2. 需要别的封地的东西，找它的领主要（看它的"供应啥"）
3. 自己封地里的"缺啥"变了，通知所有下游领主
4. 两个领主都声称供应同一样东西 = 唯一性冲突，必须合并
5. 新功能先问：这属于哪个封地？没有封地→新建封地并指定领主
