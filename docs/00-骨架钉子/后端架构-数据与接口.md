## 2. 核心 API 清单（按角色）

### 登录/公共
| API | 说明 |
|---|---|
| POST /api/login | 归属地+手机号+密码+角色 → JWT（token 内带 org_id + role） |
| GET /api/orgs | 归属地列表（村/社区） |

### 参选人（就三件事）
| API | 说明 |
|---|---|
| POST /api/materials | 提交材料（含文件上传） |
| GET /api/announcements?role=candidate | **只返回已到发布日期的公告**（未来的藏起来） |
| GET /api/announcements/:id/download | 下载公告 |
| GET /api/positions | 岗位清单（下载报名表） |

### 管理侧（超管/子管理/经办编辑）
| API | 说明 |
|---|---|
| POST /api/elections | 创建历届选举（输入 D） |
| POST /api/elections/:id/generate-stages | **日程引擎**：D → 自动生成 16 阶段日程 |
| GET/POST/PUT /api/announcements | 编辑 / 确认发布公告 |
| GET /api/materials | 查看已提交的用户材料 |
| PUT /api/materials/:id/review | 材料审核 |
| PUT /api/candidates/:id/result | 更新候选人四轮公示结果 |
| GET/PUT /api/roster | 干部花名册维护 |

## 3. 核心引擎与逻辑

### 3.1 日程引擎（发动机 · 最重要）
```
输入：D（elections.el_election_date）+ org_type（村/社区）
读取：stage_templates（16 阶段，每阶段 st_day_offset 偏移量）
生成：election_stages（每阶段真实日期 = D + 偏移量，算 start/end）
规则：改 D → 全表日程平移重算；公告跟随日程提示
```

### 3.2 公告按日期发布（参选人隐藏）
```
参选人查询：只返回 ann_publish_date <= 今天（已到日期）
管理侧查询：返回全部（含未来预告）
```

### 3.3 鉴权与权限（双保险）
```
JWT token 携带 org_id + role
数据隔离：所有查询强制 org_id 过滤（防串台）
权限：前端隐藏按钮（不渲染）+ 后端接口二次校验
参选人无：编辑公告 / 确认发布 / 看用户材料 / 改候选人结果
```

### 3.4 材料审核流转
```
参选人提交 → 管理侧查看 → 审核 → 四轮审核结果公示
（r1 材料收审 → r2 资格审核 → r3 资格复核 → r4 最终确认；前置不过后续冻结）
```
